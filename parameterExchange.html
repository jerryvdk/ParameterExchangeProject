Parameter Exchange Specification

This document describes the message structure of the parameter exchange implemented between the PC software and the PLC controller.

Every parameter value is paired with a distinct key (identification number). This architecture ensures that every machine configuration uses the same key for the identical parameter, irrespective of the specific project mapping.

Key Structure (32-bit)

The 32-bit key is packed and arranged as follows:

Bits Meaning
[31:24] (8 bits, MSB) Resource Number
[23:16] (8 bits) Sub-resource Number
[15:0] (16 bits) Offset Address

Resource Assignment Logic

Resources represent major hardware components of the machine (e.g., Axis, Robot, Gripper, Valves). Within each packed key:

  • The Resource Number identifies the type of hardware component.
  • The Sub-resource Number identifies the specific instance or element index within that component type.
  • The Offset Address targets the unique parameter variable inside that instance.

Bitwise Packing Example

If an Axis resource needs to be mapped with the following configuration details:

  • Resource ID of the axis = 100
  • Sub-resource index = 4 (representing the 4th axis instance)
  • Offset address for current position = 3

The resulting 32-bit key calculation is structured as:

key = (100 << 24) | (4 << 16) | 3

System Communication Phases

1. Startup Phase

When the PC runtime software starts, it targets a configuration query to the PLC regarding the available data keys.

  • PC → PLC: Requests the active list of parameterKeys.
  • PLC → PC: Transmits the ordered array of parameter keys calibrated for that physical machine.

This structural handshake ensures the PC maps exact parameter visibility and pre-determines the data stream sequence order. Variations in machine configurations remain structurally compatible without requiring rigid memory layouts.

2. Cyclic Read Phase

Once the initial key sequence array is registered, the PC initializes its high-frequency runtime read loop.

  • The PLC streams row parameter values in the exact historical sequence matching the parameterKeys list transmitted during startup.
  • The PC maps incoming raw telemetry arrays back to operational memory fields via the index offsets of the keys.
